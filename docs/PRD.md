# 隨「食」隨地 PRD (Product Requirements Document)

## 1. 專案概述

### 背景與動機
現代人生活節奏快，常因購買食材後不知如何處理或沒時間烹飪，導致食材過期浪費，而現有的食譜 App 太複雜且外送又貴。同時，單純的食譜 App 往往缺乏互動性，使用者容易下載後便不再使用。
我們希望透過「隨『食』隨地」結合 AI 辨識與寵物養成，讓烹飪變得像遊戲一樣有趣，同時達成惜食的目標。

### 目標用戶
- **外宿大學生/租屋族**：預算有限且廚房設備簡單，希望用現有食材快速出餐。
- **忙碌上班族**：下班後沒靈感思考菜單。
- **環保惜食者**：希望能有效利用剩餘食材，減少廚餘。

### 核心價值主張
1. **解決「食材閒置與過期浪費」的問題**：透過現有食材推薦食譜，減少浪費。
2. **消除「下班下課後思考菜單」的決策疲勞**：提供快速且個人化的菜單建議。
3. **吃的更健康**：搭配 AI 推薦食譜，達到營養均衡。
4. **克服「烹飪習慣難以持續」的動力缺口**：透過遊戲化（成就、勳章、寵物養成）機制增加黏著度。

---

## 2. 功能需求

以下為系統的主要功能，並以使用者故事（User Story）格式描述（特別著重於「使用者成就與食譜收藏」模組）：

1. **食譜收藏與管理**
   - **作為** 一名使用者，**我希望** 能將喜歡的食譜加入收藏，並在個人頁面中瀏覽已收藏的清單，**以便** 日後能快速找到並再次烹飪。

2. **成就解鎖與勳章展示**
   - **作為** 一名使用者，**我希望** 系統能在完成特定目標（如：完成 5 道料理、連續 3 天登入、收藏 10 篇食譜）時發放勳章，並在個人檔案中展示，**以便** 獲得成就感並保持烹飪的動力。

3. **烹飪數據與統計**
   - **作為** 一名使用者，**我希望** 系統能統計我的烹飪次數、消耗的食材種類或解鎖的成就數量，**以便** 清楚了解自己的進步與惜食成果。

4. **食材辨識與食譜推薦 (核心功能)**
   - **作為** 一名使用者，**我希望** 能輸入或拍攝手邊現有的食材，**以便** 系統能推薦我當下可以製作的料理，解決決策疲勞。

5. **寵物互動與養成 (遊戲化功能)**
   - **作為** 一名使用者，**我希望** 每次完成烹飪任務後能獲得點數或飼料來餵養虛擬寵物，**以便** 讓烹飪過程更像遊戲般有趣。

## 3. 非功能需求

### 技術限制
- **後端框架**：使用 Python 搭配 Flask 框架開發。
- **前端渲染**：使用 Jinja2 模板引擎進行頁面渲染，搭配 HTML/CSS/JS 或 Bootstrap。
- **資料庫**：使用 SQLite 關聯式資料庫儲存使用者資料、食譜、收藏紀錄與成就狀態。

### 效能與安全考量
- **防範 SQL Injection**：透過 ORM (如 SQLAlchemy) 或參數化查詢處理資料庫操作。
- **XSS 防護**：確保由使用者輸入的內容（如自訂食譜備註）在前端顯示時，透過 Jinja2 預設的跳脫 (escaping) 機制進行處理。
- **回應速度**：食譜查詢與收藏操作應快速回應，提供流暢的使用者體驗。

## 4. MVP 範圍 (Minimum Viable Product)

### Must Have (必須具備 - 核心功能)
- 基本食譜瀏覽與推薦（以現有資料庫為主）。
- 食譜收藏功能（加入收藏、取消收藏、查看收藏列表）。
- 基礎成就系統（例如：首抽勳章、完成第一道菜的成就）。

### Should Have (應該具備 - 重要功能)
- 個人烹飪統計資料面板（顯示收藏數、解鎖成就數）。
- 進階勳章展示牆（視覺化展示各種勳章）。
- 食材基礎輸入與簡易 AI 推薦邏輯。

### Nice to Have (有了更好 - 進階功能)
- 完整的寵物養成機制（等級、外觀變化）。
- 根據營養價值進行客製化食譜推薦。
- 社交分享功能（將解鎖的勳章分享到社群平台）。
