# 隨食隨地 - 功能需求文件 (PRD)

## 1. 專案與功能概述
- **專案名稱**：隨食隨地
- **專案描述**：現代人生活節奏快，常因購買食材後不知如何處理或沒時間烹飪，導致食材過期浪費，而現有的食譜App太複雜且外送又貴。同時，單純的食譜 App 往往缺乏互動性，使用者容易下載後便不再使用。我們希望透過「隨『食』隨地」結合 AI 辨識與寵物養成，讓烹飪變得像遊戲一樣有趣，同時達成惜食的目標。
- **目標用戶**：
  - **外宿大學生/租屋族**：預算有限且廚房設備簡單，希望用現有食材快速出餐。
  - **忙碌上班族**：下班後沒靈感思考菜單。
  - **環保惜食者**：希望能有效利用剩餘食材，減少廚餘。
- **核心價值主張**：將烹飪與惜食結合寵物養成遊戲，提升使用者的黏著度，讓清空冰箱變成一場有趣的互動體驗。

## 2. 功能需求：F-04 烹飪回報與餵食機制
- **功能名稱**：烹飪回報與餵食機制
- **功能編號**：F-04
- **功能描述**：使用者完成料理後，需提供照片上傳或勾選完成的功能。確認回報後，系統需發放「虛擬飼料」，點擊餵食後觸發寵物增加經驗值的動畫與邏輯。

### 使用者故事 (User Stories)
1. **作為** 一名使用者，**我希望** 在完成料理後能夠上傳料理照片或直接勾選完成，**以便** 記錄我的烹飪成果。
2. **作為** 一名使用者，**我希望** 系統在我成功回報料理完成後發放「虛擬飼料」，**以便** 我有道具可以餵食虛擬寵物。
3. **作為** 一名使用者，**我希望** 在收集到虛擬飼料後，能夠點擊「餵食」按鈕，**以便** 將飼料餵給寵物。
4. **作為** 一名使用者，**我希望** 點擊餵食後能看到寵物增加經驗值（EXP）的動畫，**以便** 獲得遊戲互動的成就感與視覺回饋。
5. **作為** 系統管理員，**我希望** 能夠記錄使用者的烹飪回報歷史與飼料庫存，**以便** 確保發放與消耗邏輯的正確性及防止作弊。

## 3. 非功能需求
- **技術限制**：
  - 後端：Python + Flask
  - 模板引擎：Jinja2
  - 資料庫：SQLite (需包含使用者表、烹飪紀錄表、虛擬飼料庫存表等)
  - 前端：HTML/CSS/JavaScript (需實作照片上傳預覽、餵食點擊事件與經驗值增加的動畫)
- **效能與安全考量**：
  - 圖片上傳需有檔案格式（如 JPEG, PNG）與大小限制，避免伺服器儲存空間快速耗盡。
  - 飼料的發放與消耗必須在後端透過 Transaction 進行資料庫更新，避免因為併發操作導致飼料數量異常。
  - 防止惡意大量發送料理完成請求以無限獲取飼料的行為（Rate Limiting 或次數上限）。

## 4. MVP 範圍 (Minimum Viable Product)
- **Must Have (必須有)**：
  - 簡單的料理完成勾選按鈕或表單。
  - 後端能接收完成請求並增加使用者的虛擬飼料數量。
  - 「餵食」按鈕，點擊後後端扣除飼料並增加寵物經驗值。
  - 畫面上能顯示當前持有的虛擬飼料數量。
- **Should Have (應該有)**：
  - 照片上傳功能及預覽。
  - 點擊餵食時的簡單前端動畫（如飼料飛向寵物、經驗值數字跳動）。
- **Nice to Have (可以有)**：
  - 透過 AI 圖像辨識自動判斷上傳的照片是否為食物，增加防作弊機制。
  - 累積連續天數回報給予額外飼料獎勵。
