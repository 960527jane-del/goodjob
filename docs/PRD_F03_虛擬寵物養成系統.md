# PRD - 虛擬寵物養成系統 (F-03)

## 1. 專案與功能概述

### 專案名稱
隨食隨地

### 專案描述
現代人生活節奏快，常因購買食材後不知如何處理或沒時間烹飪，導致食材過期浪費，而現有的食譜App太複雜且外送又貴。同時，單純的食譜 App 往往缺乏互動性，使用者容易下載後便不再使用。
我們希望透過「隨『食』隨地」結合 AI 辨識與寵物養成，讓烹飪變得像遊戲一樣有趣，同時達成惜食的目標。

### 功能背景與動機
單純的食譜與食材管理應用難以維持使用者的長期黏著度。為了解決這個問題，系統導入「虛擬寵物養成系統（F-03）」。透過遊戲化的機制，將使用者的烹飪與惜食行為（如：完成食譜、餵食寵物等）轉化為寵物的成長動力（經驗值與升級），藉此激勵使用者持續使用本應用，養成減少食物浪費的好習慣。

### 目標用戶
- **外宿大學生/租屋族**：預算有限且廚房設備簡單，希望用現有食材快速出餐，並透過養成互動增加自炊樂趣。
- **忙碌上班族**：下班後沒靈感思考菜單，期望藉由遊戲化機制獲得下廚的療癒感與動力。
- **環保惜食者**：希望能有效利用剩餘食材，減少廚餘，並透過虛擬寵物的陪伴獲得精神成就感。

### 核心價值主張
讓烹飪與惜食變得像遊戲一樣有趣，透過虛擬寵物的陪伴與成長（經驗值、等級、升級），提升使用者管理食材與下廚的動機與成就感。

### 2.1 功能總覽

| 編號 | 功能名稱 | 優先級 | 說明 |

| F-03-02 | 經驗值與等級顯示 | Must Have | 顯示寵物目前的等級 (Level) 與經驗值 (EXP)，並與資料庫同步。 |

### 2.2 使用者故事與驗收條件 (Acceptance Criteria)

#### F-03-01 寵物專屬展示頁面
> 作為一個**使用者**，我希望有一個**專屬的頁面來查看我的虛擬寵物**，以便了解寵物目前的狀態與外貌。

**驗收條件：**
- [ ] 系統提供 `/pet` 路由，點擊導覽列「虛擬寵物」可進入專屬頁面。
- [ ] 頁面需清楚呈現寵物的代表圖片、名字與所屬屬性。

#### F-03-02 經驗值與等級顯示
> 作為一個**使用者**，我希望在寵物頁面上能**清楚看到目前的等級與經驗值**，以便知道還差多少可以升級。

**驗收條件：**
- [ ] 顯示目前等級（如 `Lv.1`）與當前經驗值 / 升級所需經驗值（如 `EXP: 50 / 100`）。
- [ ] 數據需為當前登入使用者的真實數據，由後端從 `user_pets` 資料表即時撈取渲染。

#### F-03-03 視覺化成長進度條
> 作為一個**使用者**，我希望有一個**視覺化的進度條來顯示經驗值成長**，以便直觀地感受到我的努力成果。

**驗收條件：**
- [ ] 進度條長度比例需與 (當前經驗值 / 升級所需經驗值) 的百分比一致。
- [ ] 採用平滑的動畫效果展示進度條的填充。

#### F-03-04 餵食互動行為更新
> 作為一個**使用者**，我希望當我**點擊餵食或與寵物互動**後，寵物能即時獲得經驗值，以便立即獲得正向回饋。

**驗收條件：**
- [ ] 提供「手動餵食」或「互動」按鈕。
- [ ] 點擊餵食成功後，前台需利用 JavaScript 立即更新經驗值數值與進度條，不需整頁重新整理。

#### F-03-05 資料庫同步機制
> 作為一個**開發團隊成員**，我希望寵物養成數據能與**後端 SQLite 資料庫即時同步**，以便使用者不論重新整理或換裝置都不會遺失進度。

**驗收條件：**
- [ ] 每次經驗值變動或餵食互動需發送請求至後端更新資料庫中的 `current_exp` 與 `current_level`。
- [ ] 寫入動作必須保證事務安全性，若更新失敗需向前端返回錯誤訊息且不更改 UI。

## 3. 非功能需求

- **技術限制**：
  - 後端架構：使用 **Flask** 框架。
  - 前端渲染：使用 **Jinja2** 模板系統，並搭配 Vanilla CSS 與 JavaScript。
  - 資料庫：使用 **SQLite** 進行持久化。
- **效能考量**：
  - 寵物頁面整體載入時間需小於 2 秒。
  - 餵食/互動更新的 AJAX 響應時間需控制在 1 秒以內。
- **UI/UX 考量**：
  - 介面設計需符合年輕、活潑且具現代感的 Glassmorphism（毛玻璃效果）遊戲化風格。
  - 需支援響應式網頁設計（RWD），確保在手機版與網頁版皆能正常瀏覽。
